# Provenance: where every number in this repository comes from

Generated by `scripts/check_provenance.py --write-doc` from
`taxiout.provenance`. Every count below is summed from those manifests
rather than written down, and check 10 of that script rebuilds this file
and fails if the committed copy differs, so an entry added to the register
without regenerating this document does not get committed.

The standing rule: every number reaching a report, a note or the paper is
computed by the run that prints it, quoted from a named source with that
source beside it, or marked an estimate with an instrument and an owner.
There is no fourth kind. This file is how that becomes checkable rather
than conventional.

## The four states

Every number in a covered surface is in exactly one of four states, and
the gate's job is to prove there is no fifth.

1. **Generated** by the run that prints it. Needs no entry.
2. **Checked** against a named source, so drift fails a gate.
3. **Registered** with a one-line basis: quoted measurements, chosen
   thresholds, frozen records.
4. **Exempt**, on an explicit list with a reason: mechanism and definition.

## What the paper quotes

Check 14 runs `scripts/check_paper.py` over `docs/paper.md`. A figure there is
a decimal, a percentage, or an integer of at least
**4** digits, and every figure in a section must
appear in a file the section's `Source:` line cites and, where that line
names a section of the file in italics, in that section of it, as a
number that rounds to it at the figure's own precision and carries its
sign where the paper writes one. A figure that matches only in a frozen
dated record is *historical*, and passes only if it is listed below with a
reason. A figure the paper computes from report figures is listed below
with its arithmetic, which the check verifies: every named operand has to
be in the cited sections and the value has to round to the figure. The
register's own lists below are never read as a source. Outside `--strict`
the check prints its findings and passes; `--strict` is the paper's freeze
condition, and `--report` prints every figure with its status, section by
section, with every number in scope it matches, so a chance match can be
told from the row a sentence quotes.

**6** patterns mark a token shaped like a
figure as something else. A token they cover is counted under the
pattern's name, not dropped.

| pattern | regular expression | why |
| --- | --- | --- |
| section reference | `§\s*\d+(?:\.\d+)*` | the paper's reference to one of its own sections. It names a place in the document and measures nothing |
| heading number | `^#{1,6}\s+\d+(?:\.\d+)*\.?(?=\s)` | a section's own number at the start of its heading: the same thing as a section reference, seen from the section itself |
| year | `(?<![\w.,])(?:19\|20)\d{2}(?![\w%]\|\.\d\|,\d{3})` | a bare four-digit integer from 1900 to 2099. The paper writes every count of a thousand or more with a thousands separator, so a bare four-digit integer in it is a year: the training year, the ranking year, or the year of a cited work |
| version string | `(?i:\b(?:v\|version\|release\|python\|cpython\|odbl\|gplv?)\s?)\d+(?:\.\d+)+` | a software or license version names a release and measures nothing. A dotted number with three or more parts is never read as a figure in the first place, so this covers the two-part form after a name |
| DOI prefix | `(?<![\w.])10\.\d{4,9}(?=/)` | the registrant prefix of a DOI, before the slash. It names who registered the identifier and measures nothing |
| reference entry | `^[A-Za-z][^(]{0,250}?\. \((?:\d{4}[a-z]?\|n\.d\.)\)\..*$` | a line of the paper's reference list: an author, a year and a title, written on one line. Its pages, volume, article number and DOI name a publication and measure nothing |

## What a rebuild of an external input is pinned to

**1** external input(s) carry a pin. A pin is a claim
about what a rebuild would return. Exercising one costs the network and a
server willing to answer, so what is written here is how the pin is
applied, how a rebuild proves it was, and what would make it fail.

**the OSM movement-area geometry for the eleven airports, under `data/raw/*.json.gz`**

Rebuilt by `python scripts/fetch_osm.py --pin-from-register --force`, which pins each airport's Overpass query to its own entry in `OSM_PINS`, refuses an answer from a database older than its pin, and records, in the sidecar `data/raw/PINS.json` beside the cache, the pin each airport was fetched at, the instance that answered, the time of the fetch and the database state the answer came from.

Recoverable per airport, and only per airport, and from `OSM_PINS` rather than from the cache. The eleven entries carry **seven** distinct stamps spanning 2026-09-01T13:23:05Z to 13:32:15Z, because the fetch was sequential and unpinned and each airport was answered from whatever state its instance had ingested when it was served; one `--date` would pin eight of the eleven to a state their matrices were not built from. **The cache cannot carry them**: every answer is stamped with the answering instance's own current database state and never with the pin, so a pinned rebuild re-stamps each file with the rebuild day. The mode that read the pins from the cache, `--pin-from-cache`, would have worked exactly once and then pinned every airport to that day with no error, and it now refuses. What a rebuilt cache carries in place of the header is the sidecar, and `taxiout.osm.pin_agreement` reads a cache by whichever evidence it has: an original answer by its header stamp, a rebuilt one by its sidecar entry, which must equal `OSM_PINS` and the answer's own fetch record, and whose database stamp must not precede its pin.

- attic retention is not guaranteed. An instance may decline a query at a date this old, and one that declines is a failure to report. The mode refuses to fetch an airport the register has no pin for, because **a silently unpinned fetch is a stop**: it would replace an answer whose OSM state is recorded with one whose is not.
- **nothing in an answer's header proves the pin was applied.** The proof is the elements: `--compare FETCHED REFERENCE` matches each airport's parsed elements on type and id against the cache the matrices were built from and compares every field, and the matrices built from them are compared after that. Not the payload bytes, which differ in the header between any two answers.
- an airport unchanged since its pin answers the same pinned or not, so a match alone does not show the pin at work. The control does: `--control-date` asks the instance that answered for one airport at a date whose answer is known to differ, and reports whether it does. LIRF at 2020-01-01T00:00:00Z differs, 355 elements against 494, measured on overpass-api.de on 25 September 2026.
- the client falls back to two other mirrors when the first fails, and **on 26 September 2026 both held databases from May 2026 and could not serve a September pin**: `overpass.private.coffee` stood at 2026-05-06T03:25:00Z and `overpass.kumi.systems` at 2026-05-31T22:37:44Z. An instance cannot serve a state it has not ingested, so an answer whose `osm3s.timestamp_osm_base` precedes its pin is not the pinned answer, whatever was requested; Block 11 took LSZH from the first as it stood in May, and only `--compare` saw it.
